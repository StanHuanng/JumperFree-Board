## 文件规划

### 现有文件

- `applications/main.c`
  - 当前按键入口和初始化入口
  - 后续只负责输入事件，不直接操作 CH446Q

- `applications/CH446Q.c`
  - 当前单片 CH446Q 底层驱动
  - 后续扩展为支持 `chip_id`

- `applications/CH446Q.h`
  - CH446Q 底层接口声明

- `applications/ws2812.c`
  - 当前 LED 路径显示
  - 后续从单条路径显示升级为 bridge/net/path 显示

- `applications/ws2812.h`
  - LED 显示接口声明

- `applications/bridge_manager.c`
  - 当前 bridge 存储层

- `applications/bridge_manager.h`
  - bridge API 声明

- `CHANGELOG.md`
  - 每次完成修改后记录

### 后续新增文件

- `applications/node_map.h`
  - 定义逻辑节点编号
  - 定义节点到 CH446Q 物理入口的映射

- `applications/node_map.c`
  - 实现节点合法性检查
  - 实现 node -> candidate chip/x/y 查询

- `applications/net_manager.h`
  - 定义 net 数据结构
  - 声明 bridge -> net 的归并接口

- `applications/net_manager.c`
  - 根据 bridge 表重建 net 表
  - 支持新增/删除 bridge 后重新计算电气网络

- `applications/path_router.h`
  - 定义 path 数据结构
  - 声明 net/bridge -> path 的转换接口

- `applications/path_router.c`
  - 单片路由
  - 多片直连路由
  - 多片 hop 路由
  - 路由失败记录

- `applications/chip_matrix.h`
  - 定义多片 CH446Q 的矩阵状态缓存

- `applications/chip_matrix.c`
  - 保存目标矩阵状态
  - 保存上一次矩阵状态
  - 计算差异
  - 调用 CH446Q 驱动下发变化

## Phase 1: 完成 Bridge 驱动的单片控制

目标：外部行为不变，但 `main.c` 不再直接维护硬件连接状态。

### Task 1: 增加 `bridge_apply_all()`

**Files:**

- Modify: `applications/bridge_manager.h`
- Modify: `applications/bridge_manager.c`
- Modify: `CHANGELOG.md`

**设计：**

`bridge_apply_all()` 做最简单的全量刷新：

```c
ch446q_reset_all();

for each valid bridge:
    ch446q_connect(bridge.x, bridge.y);
```

**接口：**

```c
rt_err_t bridge_apply_all(void);
```

**行为：**

- 如果 bridge 表为空，执行 `ch446q_reset_all()` 后返回 `RT_EOK`
- 如果有 bridge，逐条恢复连接
- 暂时不做差量刷新
- 暂时不做多片 chip_id

**验证：**

- 上电默认添加 `bridge(0, 0)` 后，实际导通 `X0-Y0`
- 按键切换时，只有当前 `X0-Yn` 导通
- 多次按键循环后不会出现多个 Y 同时残留导通

---

## Phase 2: 从 `(x, y)` Bridge 升级到逻辑 Node Bridge

目标：让 bridge 不再直接表示 CH446Q 物理坐标，而是表示“两个逻辑节点之间的连接意图”。

### Task 3: 定义 Node 编号体系

**Files:**

- Create: `applications/node_map.h`
- Create: `applications/node_map.c`
- Modify: `CHANGELOG.md`

**第一版节点范围：**

```c
typedef enum
{
    NODE_X0 = 0,
    NODE_X1,
    NODE_X2,
    ...
    NODE_X15,

    NODE_Y0 = 32,
    NODE_Y1,
    NODE_Y2,
    ...
    NODE_Y7,
} node_id_t;
```

**为什么不要直接让 `NODE_Y0 = 16`：**

保留编号空洞，方便以后加入：

- 面包板行
- 电源轨
- GPIO
- ADC
- DAC
- 外部扩展接口

**接口：**

```c
rt_bool_t node_is_valid(rt_uint16_t node);
rt_bool_t node_is_x_side(rt_uint16_t node);
rt_bool_t node_is_y_side(rt_uint16_t node);
const char *node_name(rt_uint16_t node);
```

**验证：**

- `NODE_X0` 合法
- `NODE_Y7` 合法
- `999` 非法
- `NODE_X0` 被识别为 X side
- `NODE_Y0` 被识别为 Y side

## Phase 3: 单片 CH446Q 的 Node -> Crosspoint 路由

目标：把逻辑节点 bridge 转换成实际 CH446Q 的 `(x, y)`。

### Task 5: 实现单片 `node_pair_to_xy()`

**Files:**

- Modify: `applications/node_map.h`
- Modify: `applications/node_map.c`
- Modify: `CHANGELOG.md`

**接口：**

```c
typedef struct
{
    rt_uint8_t x;
    rt_uint8_t y;
    rt_bool_t valid;
} crosspoint_t;

rt_err_t node_pair_to_xy(rt_uint16_t node_a, rt_uint16_t node_b, crosspoint_t *out);
```

**规则：**

- `NODE_Xn + NODE_Ym` 可以映射为 `(x=n, y=m)`
- `NODE_Ym + NODE_Xn` 同样可以映射为 `(x=n, y=m)`
- `NODE_Xn + NODE_Xm` 暂时不支持
- `NODE_Yn + NODE_Ym` 暂时不支持

**验证：**

```c
node_pair_to_xy(NODE_X0, NODE_Y3, &out);
// out.x == 0
// out.y == 3
// out.valid == RT_TRUE
```

### Task 6: 修改 `bridge_apply_all()` 使用 Node 映射

**Files:**

- Modify: `applications/bridge_manager.c`
- Modify: `CHANGELOG.md`

**新流程：**

```text
bridge table
    -> node_pair_to_xy()
    -> ch446q_connect(x, y)
```

**失败策略：**

如果某条 bridge 暂时无法映射：

- 跳过该 bridge
- 返回 `-RT_ERROR`
- 其余可映射 bridge 仍然继续下发

**验证：**

- `bridge(NODE_X0, NODE_Y0)` 可以导通
- `bridge(NODE_X0, NODE_X1)` 不会错误导通
- 出现非法 bridge 时不会卡死系统

```text
两个 push-pull GPIO 输出不能直接同 net
```

**验证：**

- 添加 `VCC-GND` bridge 会失败
- 已存在 `VCC-X0` 时，再添加 `GND-X0` 会失败

## 风险与注意事项

### 1. 不要过早做通用图搜索

Jumperless V5 的路由不是纯通用 BFS，而是强依赖硬件拓扑的候选映射和规则选择。你这里也应该先从“固定拓扑表 + 候选路径”做起。

### 2. 不要一次把 Bridge、Net、Path 全做完

每一层都要能单独打印、单独验证。否则调试多片矩阵时会很痛苦。

### 3. F103 资源有限

优先使用：

- 固定数组
- 编译期常量
- 无 malloc
- 小结构体
- 全量重建，少量数据下更可靠

### 4. 多片硬件拓扑必须先文档化

在进入多片路由前，需要明确：

- 每片 CH446Q 的编号
- 每片 X/Y 连接到了什么
- 芯片之间有哪些互联 lane
- 哪些节点有多个候选入口
- 哪些资源不能共用

这份硬件拓扑表是后续 `node_map.c` 和 `chip_link_map.c` 的核心。
